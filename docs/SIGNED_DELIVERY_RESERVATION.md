# OLA — independently signed delivery reservation

Status: **STAGING ONLY / NO-GO**. Stacked PR #133 → PR #132 → PR #119.
This code **does not send anything** to a customer and does not execute an
agent. It adds a one-time reservation to existing durable Stripe order state
and the tenant-scoped append-only Evidence v2 ledger.

## Trust boundary

A Stripe payment alone never authorizes execution or delivery. The signed
order-release `manifest` needs two **different**, pretrusted Ed25519 public
keys: IGOR independent checker and owner Human Gate. The operator provisions
key-pins outside buyer accounts and obtains both detached signatures from
those legitimate approval workflows. Keys must not be generated by a buyer,
retrieved from an untrusted manifest, or stored with private keys in repo.

The signed payload for each role is exactly:

```python
canonical_json({
    "domain": "OLA-ORDER-DELIVERY-RELEASE-V1",
    "role": "igor",  # or "owner"
    "manifest": manifest,
}).encode("utf-8")
```

The file `approvals.json` contains `{"igor":"<base64>","owner":"<base64>"}`.
Each detached signature is raw 64-byte Ed25519, base64 encoded; each
signature binds the entire **same** manifest to its role.

The `manifest.json` requires **exactly** these fields:

| Field | Purpose |
| --- | --- |
| `tenant_id` | Original paid tenant (not inferred from a requester flag) |
| `session_id` | Exact Stripe `cs_...` Checkout Session ID |
| `stripe_event_id` | Original signed payment event ID |
| `run_id` | Already completed, independently checkable agent run |
| `source_sha` | Exact release SHA pinned by `OLA_RELEASE_SOURCE_SHA` |
| `evidence_tip` | Current full-chain tip before reservation |
| `artifact_sha256` | Hash of immutable report / artifact to be delivered |
| `recipient_sha256` | Hash of exact intended recipient identifier |
| `expires_at` | Integer UTC epoch seconds, within the next 3600 seconds |

All hash values must be lowercase 64-hex; `source_sha` is 40-hex. No raw
email, recipient identity or report contents are stored in reservation Evidence.

## Operator flow (nothing runs unless separately authorized)

```powershell
Set-Location D:\OLA
# Provision these from trusted external configuration, never from customer
# inputs or a public GitHub file. Keep private signing keys off this host.
$env:OLA_RELEASE_SOURCE_SHA = "<exact-signed-deployment-sha>"
$env:OLA_IGOR_PUBKEY_SHA256 = "<independently-verified-igor-public-pem-hash>"
$env:OLA_OWNER_PUBKEY_SHA256 = "<independently-verified-owner-public-pem-hash>"
# Match the reviewed, backed-up OLA SQLite DB in the approved environment.
$env:OLA_EG_DB_PATH = "D:\OLA\data\ola.db"

python -m scripts.reserve_signed_delivery --manifest D:\OLA\manifest.json --approvals D:\OLA\approvals.json --igor-public D:\OLA\igor-public.pem --owner-public D:\OLA\owner-public.pem

# Only after offline human approval of exact manifest, signed source,
# current tip and intended recipient:
python -m scripts.reserve_signed_delivery --manifest D:\OLA\manifest.json --approvals D:\OLA\approvals.json --igor-public D:\OLA\igor-public.pem --owner-public D:\OLA\owner-public.pem --apply
```

- No `--apply`: full signature, chain, event, payment, source, order state,
  prior independent agent-run evidence and stale-tip checks;
  response `READY_TO_RESERVE`, **zero writes**.
- Explicit `--apply`: atomically append `execution.delivery_reserved`
  (trusted producer `ola_runtime`) and set both `StripeCheckoutClaim` and
  `StripeEvent` to `DELIVERY_RESERVED`. Returns an opaque reservation ID,
  never a report or delivery link.
- Repeating the same manifest under valid, unexpired approvals returns
  `ALREADY_RESERVED` without another append or dispatch.
- Different recipient, tenant, order, artifact, run, source, expired
  signature, untrusted key, forged signer or missing execution proof blocks.

### What this DOES NOT establish

- The operator may set `OLA_RELEASE_SOURCE_SHA`; this variable is **not**
  itself a cryptographic proof of the deployed source. An independently
  verified signed deployment provenance and continuous source binding are
  required for production.
- A local configured public-key pin does **not** independently demonstrate the
  real IGOR operator's identity or separated custody. Production requires
  authenticated enrollment, rotation and revocation of both trust roots.
- There is no customer-facing delivery channel yet: no signed download,
  authenticated portal entitlement, email delivery or independent receipt.
  Do **not** report `DELIVERY_RESERVED` as `DELIVERED`.
- PostgreSQL is deliberately blocked pending separate transactional
  verification. SQLite `BEGIN IMMEDIATE` serializes reservations.
- The active paid webhook (PR #132) only creates
  `PENDING_HUMAN_AUTHORIZATION` and **never runs an agent**.
  This reservation gate requires an already verified historical or separately
  authorized execution (`PENDING_INDEPENDENT_VERIFICATION`). There is
  intentionally **no** auto-promotion from paid to executable.
- Approval after refund/dispute, external invoice compliance, one-time
  expiring portal access, actual transport retries and independent
  delivery confirmation still require production design.
- This code is not signed by owner. No external Vantage/OLA server or Stripe
  LIVE transaction has been verified with this feature.

## Release gates

1. Independently provision and verify IGOR/owner signer identity, different
   trust roots, custody/revocation, expiring one-use approvals.
2. Test legitimate separately authorized execution and final report bound to
   full order payment and exact source, not a synthetic state transition.
3. Validate order-specific entitlement and refund/chargeback status against
   provider before customer dispatch.
4. Add recipient-authenticated one-time sending and independently audited
   delivery receipt/outbox with reconciliation, never duplicate transmission.
5. Migrate/protect tenant backend state, test cross-process atomicity,
   backup/restore and failures.
6. Reconcile PR #119/#132 with PR #130 and latest `main`; signed final SHA,
   green mandatory CI, independent review, IGOR and Human Gate GO.

Tests: `python -m pytest -q tests/test_signed_delivery_reservation.py`.
Temporary testing keys are never valid for production. A passing unit test is
not a production trust-root or customer delivery attestation.
